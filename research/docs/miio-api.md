# MiIO 私有接口

**版本范围**：本地委托表、串口表、函数 VA/偏移及静态参数限制属于 `1.3.9` 样本。用户实机当前报告 `2.1.3 / MCU 0012`，不是该样本版本，详见 [版本核对](firmware.md#实机版本核对)。当前版的对应实现及完整接口集合仍待恢复；用户实测方法与旧样本静态结果应分别使用。

## 证据等级及调用边界

- **已证实／静态**：样本的注册表、处理函数、参数解析或字符串。未对设备进行调用；不保证当前设备的访问控制允许调用。
- **已证实／用户实测**：用户提供成功请求及返回；不是本次现场复测。
- **推测／待验证**：仅按名称或通用机制推导；不写成已支持接口。

下文 R/W 表示函数行为，不是恢复的账号权限模型。`—` 表示无持久属性默认值或不适用；“未知”表示未恢复。所有写接口均未执行。表内参数示例只说明格式。

网络框架首先按 `.` 分割命名空间、拼接 `_JsDlgt`，查表；无前缀时查 `user`。`FUN_4024CE54` 注册 `miIO` 15 项（原文件 `0x6D980` 起）和 `user.bind_key` 1 项（`0x6D9F8`）。函数表和字符串偏移详见 [interfaces.json](evidence/interfaces.json)。没有命中的方法走 [FUN_402488F4](evidence/decompiled/402488f4.c) / [FUN_40245E6C](evidence/decompiled/40245e6c.c) → `FUN_4024C4F4` 的 MCU 队列，而非 Wi-Fi 自动拒绝。

`get_prop` 和产品专用 `set_*` 没有出现在本地委托表或明文中；完整支持列表、参数限制及产品动作实现应继续从 MCU 获取。串口命令不能直接当成同名 LAN RPC。

## 只读验证与未决接口

下面仅为建议，未在本次分析中执行。先保存一次完整原始请求/应答并脱敏；不要高频并发查询。两个候选 getter 若返回 unknown/错误，记录该版本不支持，不改用 setter 验证。

```sh
mit --json raw "$DID" get_prop '["tds_warn_thd","lightMode"]'
mit --json raw "$DID" get_prop '["f1_usedtime","f2_usedtime","f1_usedflow","f2_usedflow","f1_totaltime","f2_totaltime","f1_totalflow","f2_totalflow"]'
```

后续最有价值的输入是同版本 MCU 固件和米家正常使用时已知 getter 的请求记录。未恢复的 TDS 数值、冲洗模式、滤芯复位方法和所有隐藏 setter 不应以猜测名称补入“已支持”表。
